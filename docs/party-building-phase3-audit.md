# 入れかえ案 第3段階：残っている問題の点検（2026/11/14）

土台：`docs/party-building-mvp-spec.md`・`docs/party-building-audit.md`（前の点検、以下「前点検」）・`docs/party-building-phase2-report.md`（第2段階の事実のまとめ）と、いまのコード・テスト。
確かめ方：組み立てたサイト（`dist/index.html`）を Playwright で開き、外への通信を止めて、関数を直接呼んだ（調べた道具は scratchpad の probe1.mjs・probe2.mjs。結果の数はこの文書に写した）。

表記：**[確認]**＝この点検で動かして確かめた／**[コード]**＝コードを読んで分かる（動かしていない）／**[未確認]**。

重要度：**Critical**＝ルールの誤り・使えない案・評価の重大な誤り／**High**＝誤解させる順位・大きな抜け・入口ごとの食い違い／**Medium**＝説明の不足・確かめの不足・使いにくさ／**Low**＝小さな速さ・見た目。

## P3-01（Critical）ダブルの評価にシングルの結果が混ざる

- **内容**：`mvpMatch(a,aSig,op,wx)` の鍵は `aSig|op.sig|wx`。`op.sig` は PokéKit の行の id（例 `garchomp`）で、**シングルとダブルで同じ**。シングルとダブルで相手の型は違う（別の集計）が、こちらの型が同じ（登録した育成）なら、先に計算した形式の結果がそのまま使われる。
- **証拠**：`76-mvp.js` の `mvpOpps`（`sig:r.id`）と `mvpMatch`。
- **再現 [確認]**：育成を登録した6匹（ドドゲザン・ガオガエン・ゴリランダー・ブリジュラス・カバルドン・アシレーヌ）で、覚えを消してダブルだけを評価した結果と、シングルを評価したあとにダブルを評価した結果が**違った**。相手の上位20匹のうち9匹が両方の形式に共通。
- **影響**：形式を切りかえて見た人のダブルの弱点・入れかえ案が、シングルの相手の型で計算される（データを混ぜない決まり B に反する）。見る順番で結果が変わる（再現性の誤り）。
- **直し方**：鍵に形式（と相手の型）を入れる。
- **テスト**：シングル→ダブルの順でも、ダブルだけでも同じ結果。

## P3-02（High）入口ごとに入れかえ案が食い違う

- **内容**：入れかえの**型**は第2段階で MVP にそろえたが、**比べ方**は入口ごとに違う。
  - 相性のいい仲間を探す（#/pair、6匹）：`mvpSwaps`（相手＝PokéKit の上位20匹・メガは1匹ずつ・大きな弱点の増減）。
  - パーティのチェックの後出し不足 `dgDefSwaps`・改善案 `dgImprove` の入れかえ・敗因の診断②：`dgTeam0`（相手＝ランクバトルの集計の上位・メガストーンを持つ匹は全員メガ・×/△/後出しの数）。
- **再現 [確認]**：上の6匹（育成なし）で、`dgDefSwaps` の3案（ガオガエン→イダイトウ♀、ガオガエン→ガブリアス、ドドゲザン→ウインディ（ヒスイ））は、`mvpCompare` ではすべて tradeoff（新しい大きな弱点 3・1・4件）。`dgImprove` の入れかえ2案（ガオガエン→イダイトウ♀、ドドゲザン→カイリュー）も tradeoff（3・2件）。
- **影響**：同じパーティで、チェックのタブは「入れかえる」を出し、相性のいい仲間の画面はそれをおすすめにしない。どちらを信じればよいか分からない。
- **直し方**：3つの入口の入れかえ案を、出す前に `mvpEvalTeam`→`mvpCompare` で確かめ、**新しい大きな弱点ができる案（cm>0）は出さない**。出さなかった数と理由は書く。MVP のデータが無い形式では今までどおり。判定（×の数など）そのものは変えない。
- **テスト**：3つの入口の案はどれも `mvpCompare` で cm=0。

## P3-03（High）メガの匹を別のメガの匹に替えるとき

- **内容**：`mvpCompare` は同じ鍵の場合どうしで比べ、外す匹のメガの場合は「メガなし」とだけ比べる。パーティにほかのメガがいると「メガなし」の場合は無いので、外す匹のメガの場合（lost）と入れる匹のメガの場合（added）は**どちらとも比べられない**。
- **再現 [確認]**：メガボーマンダ・メガルカリオZ＋4匹で、ルカリオ（ルカリオナイトZ）をガブリアス（ガブリアスナイトZ）に替える。比べたのは「メガボーマンダ」どうしだけ。メガルカリオZの場合の大きな弱点11件、メガガブリアスZの場合の12件は判定に入らない。
- **影響**：新しいメガの場合が悪くなっても、おすすめ（better）になりうる。
- **直し方**：外す匹のメガ↔入れる匹のメガを1組として比べる。外す匹のメガだけ（入れる匹がメガでない）ならメガなし、無ければ「比べられない場合」として案の札に出す。
- **テスト**：上の再現で、その組が比べられる。

## P3-04（High）失われる役わりを見ていない

- **内容**：大きな弱点は相手ごとの1対1の数だけ。外す匹だけが持っていた技・特性（トリックルーム・おいかぜ・天気・設置技を消す・ねこだまし・いかく・壁・このゆびとまれ・交代技・先制技）は、比べ方にも画面にも出ない。天気だけは `teamWx` で計算に入る（天気が変わると1対1が変わる）が、「天気を失う」とは書かれない。
- **証拠 [コード]**：`mvpCompare` の材料は `scen.weak` だけ。
- **影響**：トリックルームの構築でトリックルームの唯一の使い手を外す案が、1対1の数が良ければおすすめになる（前点検 B-8 の10・11）。
- **直し方**：型（技・特性）から役わりを数える `mvpRoles`。6匹でその匹だけが持つ役わりを外すときは「失われる役わり」として案に出す。**素早さの操作（トリックルーム・おいかぜ）と天気**を失う案はおすすめにせず「良くなるところと悪くなるところがある」に入れる（数の重みは足さない）。入れる匹が加える役わりも出す。
- **テスト**：トリックルームの使い手を外す案がおすすめにならない。

## P3-05（Critical・直さない）診断のメガシンカの同時計算（前点検 B-1-1）

- **内容**：`dgTeam0` はメガストーンを持つ匹を全員メガの姿で計算するので、◎（2匹以上で安定）の2匹が両方メガ、ということが起こる（前点検で確認）。
- **直さない理由**：診断の ◎○△× を「メガの場合ごと」に分けるには、まとめ・相手ごとの対応力・選出・改善案のすべての画面の見せ方を決め直す必要がある（依頼主の判断）。テストも多い（diag）。
- **第3段階でしたこと**：入れかえ案への影響は P3-02 で止める（入れかえ案は1匹ずつのメガで確かめる）。
- **次に要るもの**：診断で、どのメガの場合を見せるか（いちばん悪い場合／選んだメガ／場合ごと）を依頼主が決める。

## P3-06（Medium）使えない・未確認の匹がパーティにいる

- **再現 [確認]**：ビビヨン（unverified）を入れた6匹で `mvpWeakHTML` に注意が出ない。
- **直し方**：いまの6匹の「使えるか」を出す（使えない／未確認）。
- **テスト**：注意が出る。

## P3-07（Medium）外す匹がしていたこと

- **内容**：案には「なくなる大きな弱点」「新しくできる弱点」は出るが、外す匹と入れる匹がそれぞれ何匹の相手に有利・後出し・受けができるかは出ない（3つを分けて数えているのに、画面では分けて見えない）。
- **直し方**：同じ場合で、その枠の匹の「1対1で有利」「後出しして勝てる」「2回耐えられる」の数を、外す匹→入れる匹で出す。
- **テスト**：数が `scen.rows[].z[i]` と一致。

## P3-08（Medium）ダブルで見ていないこと

- `mvpLimitsHTML` の中（たたんだ所）だけ。ダブルのときは、入れかえ案の上に、いつも見える形で書く。

## P3-09（Medium）評価していない相手

- `mvpOpps` の `skip`（型が組めない相手）は計算から外れるが、画面に数が出ない。弱くないとみなしたように見える。画面に出す。

## P3-10（Medium）「半分以上削れる匹がいない」

- 判定は `me.max>=50`（いちばん高い乱数）。「いちばん高い乱数でも半分に届かない」と書く。判定は変えない。

## P3-11（Medium・直さない）1対1で扱えない技を含む候補

- **[確認]** シングル149行のうち、使えると確認できた匹で `IMP_NOMV` の技（りゅうせいぐん4・リーフストーム3・オーバーヒート2・カウンター2・ミラーコート2・ゴールドラッシュ・アーマーキャノン・アイスハンマー ほか）のため外れるもの28行（ダブル19行）。
- 技を勝手に別の技に替えるのは型をつくり変えることになる（決まり B）。自分の能力が下がる技・ためる技を1対1で計算できるようにするのは次の段階。画面の「比べなかった候補」に理由つきで出ている。

## P3-12（Medium・止めたまま）メガストーンの可否

- **[確認]** メガの行42件（シングル）が、メガストーンの M-C での可否が未確認のため候補にならない。公式の一覧が要る（仕様の6章1）。

## P3-13（Low）前段のしぼりこみの天気

- `mvpSwaps` の前段は `mvpMatch(a,sig,op,'')`（天気なし）。本番の比べ方はパーティの天気の中。雨・晴れのパーティで、天気で強くなる候補が前段で落ちうる。いまのパーティの天気（`E0.wx`）を使う。

## P3-14・P3-15・P3-16（Low）

- P3-14：くわしく比べるのは前段の上位8匹（約0.2秒）。画面に「くわしく調べた候補8匹」と書いてある。
- P3-15：`dgDefSwaps` の同点は合計種族値。P3-02 の確かめのあとは影響が小さい。
- P3-16：対応しない3行は相手の上位20匹の外。候補にもならないが、画面の「比べなかった候補」には出ない（対応しない行は `pool.unmapped` にだけある）。

## 確かめたが問題でなかったこと

- 同じ入力で同じ結果：行の並びを逆にしても同じ（既存テスト）。同点の並びは図鑑番号→枠の番号で決まる。
- 古い計算の結果で上書きしない（`MVP_TOK`、既存テスト）。
- 持ち物の重なり：候補は残りの5匹と重ならない（既存テスト）。パーティの登録した重なりは表示する。
- 使用率で並べていない（並びの式に使用率・合計種族値は無い）。
- PokéKit の `evs` は使っていない。
- 選出の組み合わせを数えていない。
- 速さ：同じ6匹の入れかえ案はキャッシュなしで約0.23秒、2回目は約0.11秒（PC の Chromium）。
