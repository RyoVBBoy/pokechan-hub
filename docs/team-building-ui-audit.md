# 1匹から組む：画面の点検（2026/11/14）

依頼：「Pokémon Team Building UI/UX Overhaul」。実際の画面（Playwright・幅390px・暗い色と明るい色）を描いて点検した。前の段階（③の作りかえ、`docs/manual-team-builder-ui-redesign-report.md`）のあとの状態。

## 1. 見つけた問題

### 全体
- 6匹の並びが種族値の形（`stamp`）だけで、名前もタイプも無い（①の上位パーティ・②の案）。形だけでは何のポケモンか分からない。
- 道の名前の「②」が「こだわり条件で組む」。依頼の名前は「条件から組む」。
- 下の帯が、①②でも「パーティに入れる」（③の下書き＝多くは1匹）を出していた。①②の各カードの「パーティに入れる」（その案・そのパーティ）と同じ名前の操作が2つ並び、どちらが何を入れるのか分かりにくい。

### ① 環境のパーティ
- 見出しの下に長い説明（登録されたものだけ・並べ方・大会は区別していない）と、調べた範囲の文が、いつも出ている。
- 見出し「〇〇が入った上位パーティ」が長く、スマホで「上位パ／ーティ」と切れる。
- 各パーティの下に枠線の丸いボタン2つ（「③ 自分で組むで開く」「パーティに入れる」）。
- 「集計の型」「一緒に使われる仲間」が、実際のパーティと同じ見た目で続き、「実際に登録されたもの」と「集計（参考）」の区別が見た目で分からない。
- 読み込めなかったときの表示だけ、古い形（古い見出し・枠線のボタン）のままだった（テストで見つけた）。

### ② 条件から組む（2つの案）
- 案A・案Bのカードそれぞれに、同じ長い説明・同じ「必ず守る条件」の一覧（5行）・「できれば守る条件」の一覧が入り、同じことを2回読ませる。
- 2つの案の差（大きな弱点の数）が、案Aの中の注意の箱「勝ちやすさの面でゆずったところ」にしか無く、比べにくい。
- 6匹は形だけ（名前はあるがタイプなし）。
- 操作は枠線の丸いボタン2つ。

### ③ 自分で組む
- 前の段階で作りかえ済み（まとめ・1行ずつ・短い候補・くわしくは開いたときだけ）。残りは名前の横のタイプが無いこと。

## 2. 使い回せるもの

| 部品 | 場所 | 使い方 |
|---|---|---|
| 計算（大きな弱点・候補・比べ方・案） | `76-mvp.js`・`77-teambuild.js` の `tbAnalyze`・`tbCands`・`tbProps` | そのまま。数は描くだけ |
| 6匹の並び `tbSixOne` | 77-teambuild.js（前の作業で追加） | 名前に加えてタイプの札 |

| 画像の差し込み口 `ART_URL` | 02-data.js（null）・`artHTML`（04-common.js、図鑑だけ） | `monArt` で同じ差し込み口を1匹から組む全体に。許諾のある画像が決まったら1か所を変えるだけ |

## 3. 画像のしくみ（くわしくは報告書の6・7・8）

- リポジトリにポケモンの画像は1枚も無い（`src/static/` はサイトのマーク・アプリのアイコン・共有用の画像だけ）。
- 図鑑・検索・ほかの画面は、どこも種族値の形（`stamp`）。依頼主との取り決め（CLAUDE.md「守ること」：公式の画像・アイコン・ロゴは使わない。直接のリンクで表示するのも同じ扱い。株式会社ポケモンに問い合わせ中）による。
- 差し込み口 `ART_URL` は「公式の許諾を得たら 'img/{no}.png' のように設定」とコメントがあり、いまは null。図鑑のページの上だけが使っていた。

## 4. 直す範囲

表示だけ：道の名前・下の帯の操作・①の見出しと札と操作と「このリストについて」・読み込めないときの形・②の条件の表（1回）と比べる箱と同じ形の2枚・6匹のタイプの札・③の名前の横のタイプ・画像の差し込み口を1匹から組む全体に（`monArt`、読めない画像は同じ匹の形）。計算・並べ方・保存は変えない。新しい画像・外の画像は入れない。
