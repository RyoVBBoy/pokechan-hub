## 2. つなぎ直しが要るもの

- 図鑑の「このポケモンから組む」は今 `#/pair/番号` で、**いまのパーティに直接入れる**（枠がいっぱいなら確かめて入れかえ）。新しい入口は、パーティを書きかえない下書き（`#/tb/番号`）にする。`#/pair` はそのまま残す。
- `kdBuild` は `team`（いまのパーティ）と `KD`（こだわり条件の保存）を読む。下書きで使うときは一時的に入れかえて必ず戻す。
- 「パーティ作りの進み具合」（54-steps.js）の案内は今までどおり（変えない）。

## 3. 足りないデータ・しくみ

- **6匹のパーティのデータ**：サイトにあるのは上位パーティ（利用者・運営者の登録と、記事から2つ以上の出典で一致したもの）だけ。件数はサーバーしだいで、この環境では読めない（[未確認]）。
- **大会の結果**は区別して持っていない（シーズン名と順位だけ）。大会のパーティとして見せない。
- **一緒に使われる仲間**：PokéKit の JSON に `teammates` がある [確認]。そのポケモンを使った人のうち、その仲間も入れていた人の割合で、**6匹のパーティそのものではない**。いまの `75-mvp-data.js` には入っていなかった → 同じ月（2026-10）・同じ対戦数の版を取り直して足す（ほかの値は変わらないことを確かめる）。
- 勝率・パーティ単位の成績のデータは無い。作らない。

## 5. 作り方（提案）

- 新しいファイル `src/js/77-teambuild.js`、画面 `#/tb/番号`（下書きを始める）・`#/tb`（続きを開く）。
- 下書き `TB`（localStorage `pctb`）：起点のポケモン・形式・メンバー（育成つき）・こだわり条件・開いている道（①②③）。**パーティとは別**。パーティに入れるときだけ `useTeam`。
- ③自分で組む：6枠（起点は1枠目・外せない）、追加・外す・入れかえ、分析（`mvpEvalTeam`）、候補（PokéKit の型が組める・使えると確認できた匹を、入れた後の6匹で計算し直して、減る弱点と増える弱点を出す）。6匹そろえば `mvpSwaps` の入れかえ案。
- ①環境のパーティ：上位パーティから起点を含むものを、出典の種類（運営者が確認・本人の申告・記事の自動集計）ごとに。下に PokéKit の型と仲間の割合（Showdown の集計と明記）。
- ②こだわり条件：必ず守る条件（入れたい匹・入れたくない匹・メガシンカ）と、できれば守る条件（構築のタイプ）を分ける。矛盾は理由つきで止める。案は2つ：「こだわり優先」（kdBuild、当サイトが組んだ理論上の型）と「勝ちやすさ寄り」（入れかえ案と同じ計算で、大きな弱点が少なくなる匹を1匹ずつ選ぶ。集計の型）。
- 3つの道は同じ下書きを見る。①②の案は「自分で組むで開く」で下書きに入る（上書きの前は確かめる）。

## 6. ぶつかりうる所

- `kdBuild` を下書きで呼ぶとき、`team`・`KD` を戻し忘れるといまのパーティが変わる → `impWith` と try/finally。テストで確かめる。
- `pickMon` の `add` はいまのパーティで隠すので、下書きでは使わず、重なりは自分で確かめる。
- ダブルは1対1の計算だけ（ねこだまし・おいかぜ・範囲技などは評価しない）→ 画面に書く。
