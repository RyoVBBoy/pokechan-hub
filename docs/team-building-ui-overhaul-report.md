## 1. はじめの点検（要約）

## 4. ② 2つの案

- **条件は上の表に1回だけ**（必ず守る条件／できれば守る条件、列は A・B、✓＝守れた・△＝できれば守る条件を守れなかった・×＝必ず守る条件を守れなかった）。案のカードの中から条件の一覧を外した。△の理由は各案の「計算のくわしい結果」に。
- **比べる箱**：「大きな弱点（メガシンカなしの場合・上位20匹の相手）A 16件 vs B 5件 → 案Bの方が11件少ない」と、その数の意味（上位の相手1匹ごとの困りごとの数。少ないほど勝ちやすいとは限らず、勝率ではない。どちらも理論上の計算）。数は `tbProps` の `critN` のまま。
- **同じ形の2枚**：A／B の印・「案A こだわり優先：あなたの条件を優先」「案B 勝ちやすさ寄り：弱点の少なさを優先（必ず守る条件は守る）」・6匹（絵・名前・タイプの札・メガの札）・3つの数（大きな弱点・できれば守る条件の数・型が理論上か集計か）・直したところ・「編集する ›」（③の下書きに）と「パーティに入れる」。パソコン（700px 以上）では横に2枚並ぶ。
- 前の長い説明（各案の考え方・理論上・勝率ではない）は、比べる箱の1文と各案の一言にまとめた。

## 6. ポケモンの見た目

- **6匹の並び `tbSixOne`**（①の上位パーティ・②の案）：52px の絵＋名前＋タイプの札（当サイトの色と略字。例：竜・氷）＋メガストーンを持てば「メガ」。3匹ずつ2段（スマホでも小さくしない）、パソコンは①で6匹1段。
- **タイプの札 `tbTyB`**：③のパーティの行・候補・仲間の一覧にも。
- **絵 `monArt(p)`**（04-common.js）：画像の差し込み口 `ART_URL` があれば、図鑑と同じ番号（`byNo` の鍵）の画像、無ければ種族値の形。いまは差し込み口が空（null）なので**形**。1匹から組むの画面の絵はすべてこれを通る（9か所）。
- **読めない画像**：インラインの onerror は CSP で止まるので、document の capture で受けて、**同じ番号のポケモンの形**に置きかえる（ほかのポケモンの画像にはしない。置きかえたものにも番号を残し、テストで同じポケモンであることを確かめる）。
- **できなかったこと**：ポケモンそのものの画像は出していない（下の7・8）。代わりに、名前・タイプの札・メガの札で見分けられるようにした。

## 8. 権利と商用（確かめたこと／確かめていないこと）

### 確かめたこと（このリポジトリの中の事実）
- ポケモンの画像は1枚も入っていない。外の画像も読んでいない（`ART_URL=null`）。
- 依頼主との取り決め（CLAUDE.md「守ること」）：公式の画像・アイコン・ロゴは使わない（サイトの部品・アプリでの使用は Pokémon Champions の動画・静止画ガイドラインの範囲外）。直接のリンクで公式の画像を表示するのも同じ扱いでしない（2026/11/06 合意）。画像を使ってよいかは依頼主が株式会社ポケモンに問い合わせ中（返事待ち）。自分で撮ったスクリーンショットは、非営利のうちは記事に使える（広告を入れたら外す）。
- サイトのフッターに「非公式のファンサイト・名称は各権利者の商標」と書いてある。

### 確かめていないこと（法律の確認が要る。今回この環境からは外のページを読んでいない）

### 作り方の決めごと（あとで差しかえられるように）
- 画像の置き場所は `ART_URL` だけ。ポケモンのデータ・計算・1匹から組むの画面からは分けてある。許諾のある画像が決まったら、画像を `img/番号.png` のように置き、`ART_URL='img/{no}.png'` にするだけで、図鑑の上と1匹から組むの全体に出る。
- 外の画像サービス・新しいサーバーは足していない。AI で作った似せた絵も使っていない。

## 12.7 追加：タイプのエンブレム（同日 依頼主の見本の画像「複数タイプは、それぞれのタイプを半分に切ってくっつける」）

- `typeEmblem(p)`（04-common.js）：当サイトのタイプの絵 `TICON` とタイプの色だけで描く。1つのタイプはその絵をそのまま。2つのタイプは、1つ目の絵の左半分と2つ目の絵の右半分を、少しななめの切り口でくっつける（切り抜き clipPath）。ふちにそれぞれの色のうすい光（feDropShadow）。読み上げは「〇〇のタイプ：ドラゴン・こおり」。同じ画面に何個あっても切り抜き・光の番号がぶつからないよう、1つずつ番号を変える。
- 使う所（1匹から組むの中だけ。図鑑やほかの画面は変えていない）：6匹のカードの右上の大きくうすい透かし・③のパーティの行（前の色の帯の代わり）・1匹ずつの働き・候補・下の帯・最初の1匹の見出し・仲間の一覧（`monArt` の画像が無いときの代わりを、六角形の種族値の形からこのエンブレムに）。画像の差し込み口 `ART_URL` があれば今までどおり画像、読めなければ同じポケモンのエンブレム。
- 画面：同日 依頼主「このテイストで」（前のうすい透かしの見た目）に合わせ、6匹のカードのエンブレムは右上に大きく（72px、379px 以下は60px）うすく（透明度0.2、光なし）透かす形にし、「ずかん↗」は番号の行に戻した。名前のための右の余白が要らなくなったので、どの幅でも2列のまま。320・390・1280px で確かめた。
- テスト：teambuild 132項目すべて合格（足したもの：2つのタイプは左半分と右半分をそれぞれのタイプの色で・1つのタイプはそのまま・読み上げ・番号がぶつからない。直したもの：画像が読めないときは同じポケモンのエンブレム、③の行・1匹から組むの中に六角形が出ない）。
