## 3. 仕様との違い・決めたこと

- 独立評価の対応づけ（`tests/ai-eval-b1-acceptance.mjs` の SETUP・OUTCOME に全部書いた）：「hold」は「候補を作らない」か「どの候補も過去・未確認と書いて保留の理由を出す」。現行の確認済みの記録が無いときは、過去のシーズンの記録を「今のおすすめではない」と書いて出す（候補を隠さない）。「blocked」は 503（停止・予算）か、ほかの人の会話の番号を使わずに候補を出さないこと。「それでお願いします」「同じ質問です」は前の条件のまま出し直す続きとして扱った。
- 独立評価に合わせて足した読み取り：「何組めばいい」「無難な」「初心者向け」「人気構築」「勝率1位」などのおすすめの言い方、名前＋「固定・入れて・外さないで・以外・なしで」で始まる相談、「できれば」（必須にせず並びと理由だけ）、「メガじゃなくて通常の方」（メガストーンなし）、同じポケモンを入れる・外すの両方（どちらか聞く）、「やっぱりシングルで」（条件だけ引きつぎ候補を取り直す）、「ダブル」だけの返事（前に形式を聞いた相談を続ける）、「最新情報」（公式のお知らせの画面へ）、ほかのゲームの名前（その会話の候補を使わない）。名前のあとの「入れる」と「外す」の言葉は、先に出てくるほうで決める。
- 質問に書かれた、ここでは満たさない求め（初心者向けか・勝てる保証・勝率・技や持ち物・証拠の画像）は、答えを止めずに知らせのカードを付ける。

- 根拠の種類に `site_verified`（「運営が証拠を確認した記録」）を足した。Stage A の5種類（公式資料・実機で確認・外部参照…）のどれにも当たらないため。
- 「今おすすめ」の候補の並びは、新しいシーズン → 順位 → レート（モデルが並べかえるときも同じ候補の中だけ）。勝てる順・強さの順位とは書かない。
- 戦い方は、登録された技・特性が無い匹からは決めない（「決められません」と書く）。`dgTeam` などの計算は Worker に移していない（画面と同じ版で照合する仕組みが要るため、B2 以降で検討）。
- 会話の状態はサーバーの期限付きの行（署名つきの状態ではなく）。

## 4. 止まっていること（依頼主・運営の確認が要る）

1. **現行レギュレーションの確認済みの記録が無い**（`worker/ai-rulesets.json` は空）。このままでは B1 の答えはいつも「過去のシーズンの記録（今のおすすめとは言えない）」になる。公式の資料の URL・期間・形式・対応するシーズン・参加できるポケモンを確かめて登録する必要がある。
2. **実際の OpenAI の呼び出しは未実施**（承認・契約・データの保持と地域・未成年者への対応の審査が先）。有効にするには、検証環境だけに `AI_PROVIDER=openai`・`AI_OPENAI_APPROVED=1`・`AI_FREE_TEXT_APPROVED=1`・`OPENAI_API_KEY`（Cloudflare のシークレット）・`AI_OPENAI_MODEL` と、AI_DB の `ai_prices` にそのモデルの単価の行を入れる。`store:false` 以外の保持条件は提供元側で別に確認。
3. **移行 `0002_ai_b1.sql` を AI_DB に当てる必要がある**。Worker は schema '2' を確かめるので、当てないまま Worker を出すと Stage A も 503（`ai_db_unmigrated`）になる（AI は既定で無効なので利用者には影響しない）。
4. 実機（iPhone のキーボードを出したときの候補カードの見え方）は未確認。
5. 人手のレビュー（戦い方に沿った理由・次の行動の妥当性）は未実施。実 API 承認後は同じケースを複数回流す。
