# パーティチェックからのAI相談

2026-11-27 JST。先行導入はパーティチェック1か所。AI専用ブランチのStage Bを共通基盤として使う。独立チャットを導入の前提にしない。ダメージ計算と選出アシストへのボタン追加は次段階。

## 画面と操作

- パーティのチェックタブで「戦い方・強み」の要約の直後に、控えめな「この結果をAIに相談する」ボタンを置く。本番main `f2150e1` では `src/js/13-party.js` の `teamRender` が `stHTML/stFill` と診断を組み立てる。要約を描画する実際の箇所を使用し、`63-diag-ui.js` の未使用のHTML生成関数に入口を置かない。診断結果がまだない場合は表示しない。
- 押すとスマホは下から、PCは横から相談パネルを開く。パネルには「相談に使う情報」（対象パーティ・対戦形式・診断の前提）と質問例、自由入力、残り回数、閉じる操作を表示する。最初の質問例は「この6匹の強みを活かすには？」「このポケモンを残すなら、どこを見直す？」程度。ボタンを押すだけでは質問を送信しない。
- 最初の相談に対し、強みとその根拠、次の練習で試すことを1つ表示する。根拠は元の診断の要約・対応する結果にリンクまたは復帰できる形にする。入れ替え案・数値は再計算済みの候補に限る。確かめられない場合は前提を示し、断定を保留する。パーティの保存・差し替えは利用者が既存画面から行う。

## 相談に渡すデータ

- 結果を開いた時点のスナップショットをメモリに固定。ゲーム、形式、ポケモンとフォルムID、必要な育成項目、診断結果の識別子・前提・版を許可リストで抽出する。元HTML・アカウント名・パーティ名・個人メモ・対戦相手の私的な情報は渡さない。実サービスに送る対象は送信前に確認できるようにする。
- クライアント由来の結果は「この端末で計算した結果」。サーバーで再計算か照合ができた場合だけ、その旨を表示する。AIは既存の診断・計算・出典の範囲で説明する。集計なしの診断を使用率上位の集計として表現しない。
- パーティ、育成、形式、対象版または集計条件が変わったら、次の送信前に「結果が更新されました」と示し、新しい結果で相談を始める。続きの相談では、残したいポケモンなどの条件を同一スナップショットに限って引き継ぐ。画面を閉じても試合状態のサーバー側判定を解除しない。ログアウト・退会・アカウント切替で会話と下書き、表示待ちの応答を消す。

## 動作・公開条件

- 既存のAI認証・無料枠（1日5回答・月30回答）・回答カード・停止設定を再利用。パネルを開く、確認に答える、制限・保留・失敗だけでは無料回答枠を使わない。
- [フェアプレイ仕様](./stage-b-fair-play-spec.md) をサーバー側で適用する。入口のツール名や「練習」との自己申告で制限を解除しない。進行中の個別判断では構築・選出・計算を呼ばず、候補や個別指示を出さない。既知の終了判定の問題は公開前に修正する。対戦状況が不明で回答が変わる場合は確認する。
- PC・スマホでボタンの位置、パネルの開閉とフォーカス復帰、キーボード表示時に質問欄と回答末尾が見えることを試験する。無効設定、未ログイン、既存診断の未完了、結果変更、別アカウントへの遅延応答、送信重複、上限、フェアプレイ制限も検証。正しい対象と診断根拠で「この6匹で次に試すこと」が1つ決まることを完成条件とする。
- 実装は専用ブランチ、既定で無効、模擬通信から。実API利用、課金、本番反映は別途承認。
