## A. What Changed（変えたこと）

チェックタブの並び（上から）：

1. **このパーティの戦い方**（新しい `src/js/78-strategy.js` の `stHTML`/`stFill`）
   - 戦い方の型：`teamArch` の札（天気・トリックルーム・おいかぜ・対面/サイクル/積み）と、型ごとの進め方の一文 `ST_APPROACH`、理由。型が決まらなければ「まだはっきりした型は見つかっていません」とだけ書く（型を作らない）。天気を作れても得をする仲間がいなければ「天気を雨にできる（いまは雨で得をする仲間がいません）」。
   - メガシンカの選び方の札（`dgMegaBarHTML`、前は「診断のまとめ」にあった）と「メガシンカしない場合と比べる」（開いたときだけ `dgTeam1(…,-1)` で別に計算。上の結果には混ぜない）。
   - 推定の明記：技を登録していない匹の名前と「使用率の高い型で計算した推定」。ダブルは1対1の組み合わせであること。
2. **パーティの強み**（3つまで、どれもポケモンの名前＋「使い方」）：天気で得をする仲間／トリックルームを張る役と遅い匹／上から倒せる数がいちばん多い匹（上位の4分の1以上のときだけ）／攻撃を受けられる数がいちばん多い匹／弱点を受け合える2匹（partyCheck のよいところ）／2匹以上で安定して対応できる相手の数（中心の匹の名前つき）。見つからなければ「目立った強みはまだ見つかりませんでした」。
3. **おすすめの選出と先発**：`dgSelect` の1番（`selPlan` 経由）。匹ごとに役わりの札（先発・上から倒す・受け・場づくりの技・積みエース・詰め役）と、有利に戦える相手の数。「使用率の上位N匹を相手にした基本の選出…いつも最適とは限らない」と明記。天気・トリックルームの作る役が選出に入っていなければ、そのことを注意として出す。「この組み合わせを選出にする」ボタン。
4. **戦い方の流れ（目安）**：序盤（場づくりの技／トリックルーム／先発）→中盤（残りの匹）→終盤（`selPlan.finWhy` の詰め役。理由がなければ「はっきりしません」と書く）。「必ずこの通りになるわけではありません」。
5. **気をつけたい相手・場面**（前の「診断のまとめ」。強みと選出をここから外し、状態・優先ポイント・まず試したい改善を残した）と、**苦手になりやすい場面**（前の「気をつけたい場面」＝敗因の診断。名前だけ変更）。
6. **くわしい分析**（`<details id="dg-adv">`、はじめはたたむ。開いた状態は sessionStorage `pcdgadv`）：相手ごとの対応力・改善案・パーティのチェックの全項目・参考・計算の前提。中身は前と同じ。中へ移動するリンク（優先ポイント・ttJump）は自動で開く（`dgAdvOpen`）。
