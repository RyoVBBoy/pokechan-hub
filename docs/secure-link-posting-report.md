## 3. Validation order (server, authoritative)
Per-UID attempt slot (counts rejected attempts; atomic single-statement INSERT…SELECT: 10 s gap, 12/h, 40/day) → feature prerequisites (SANCTIONS_ON, email key) → token `email_verified` + record HMAC → `lkValidate`: type → length ≤2048 UTF-8 bytes **before** any normalization → printable ASCII only (rejects controls, spaces, bidi/zero-width, full-width, raw non-ASCII/IDN) → no `\` and no `"<>\`{}|^` → scheme exactly `https://` → no userinfo, no explicit port, no `%` in host, well-formed percent-encoding → decoded form free of controls/bidi/zero-width/backslash → WHATWG `URL` parse → input host must equal parsed host (catches `0x7f.1`, trailing dots, etc.) → not IP literal, ≥2 labels, LDH labels, alphabetic or `xn--` TLD → not internal/reserved suffixes, shorteners, external-contact hosts → no redirect-looking params/path, no sensitive params (query and fragment) → NG words on decoded URL → canonical `URL.href` re-checked ≤2048. Inline extraction: exactly one `https?://` ASCII token, trailing punctuation returned to text, must be delimited; >1 → reject; remaining text must pass legacy `ngCheck` (so bare/obfuscated domains and second links are rejected). Stored: canonical href (with fragment). Sent to Web Risk: canonical href **without** fragment.

## 4. Threat checks
Adapter `lkThreat`: fixed endpoint, key in header only, `redirect:'manual'`, timeout, 8 KB capped streaming read, strict response schema (only `threat`, known threat types, RFC 3339 `expireTime`), all four threat types requested, global concurrency via D1 leases (`LINKS_WEBRISK_CONC`), single-row day+month budget (UTC), shared cache keyed by policy version + URL (clean ≤ `LINKS_CLEAN_TTL_MIN`; unsafe exactly until provider `expireTime`; ≤5000 clean rows, unsafe never evicted while valid). Any error/timeout/quota/malformed/missing key → link refused (503) or left inert; non-link posts unaffected. No destination fetch anywhere (asserted in tests by recording every outbound request).

## 5. Moderation and verified-email registry
`sanctions` (kind uid/email, permanent or `expires_at`, reason, evidence id, source, actor = salted hash of admin IP, status, appeal, parent), `sanction_events` (audit). Perpetrator: permanent UID sanction + permanent email tombstones for every recorded verified-email hash of that UID; none recorded → `email:'unresolved'` (no invented association). Linked/temporary: 90 days default or 3–6 calendar months. Enforcement independent of flags; expiry sweep hourly (cron `0 * * * *`), on the user's own writes, and in periodic cleanup — only `banned=2` ever returns to 0. Email: Firebase-verified claim only (never request body); normalization = trim, NFC, lowercase whole address, IDN domain → ASCII, **no** plus/dot folding; HMAC-SHA-256 with versioned key and previous-key rotation (auto re-key). Deleting an account removes `user_emails`; sanctions persist. Firebase-side disable/revocation is implemented as code (`fb_sync` + `tools/firebase-adapter`, blocking functions in `tools/firebase-blocking`) and mock/local-D1 tested only; it is not deployed. Service-side denial (the gate) remains authoritative (see §7).
