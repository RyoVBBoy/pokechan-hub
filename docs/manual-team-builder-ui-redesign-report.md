## 1. 見つけた問題（前の画面を 390px で実際に描いて確かめた）

- **最初の画面にまとめが無い**：上から、最初の1匹 → 3つの道の大きなカード（説明の文つき）→ 6つの大きな枠（「集計の型（PokéKit・Showdown の集計）」の長い文字・ボタン2つ・育成）が並び、パーティの状態は2画面目より下だった。
- **3つの道のカード**に説明の文があり、カードが大きく高さもそろっていなかった。
- **大きな弱点の一覧**（場合ごと・相手ごとの長い文）がいちばん上に全部出ていた。
- **タイプの相性**は18タイプを同じ強さで2列に並べていて、問題のタイプが目立たなかった。
- **1匹ずつの働き**は、匹ごとに3つの数・相手の名前・注意が全部出ていて長かった。
- **候補のカード**は、場合ごとの数・なくなる弱点5件・新しい弱点4件・役わり・重なり・仲間の割合が全部出ていて、1枚が画面の高さ近くあった。
- **いまの匹と比べる**は、入れかえ案のカードをそのまま出していて、良くなる・悪くなるが長い文の中に埋もれていた。
- **下の帯**（パーティに入れる）は高さ約70px で、下のメニューから31px 上に浮いていた。
- 前の版の「くわしい分析」の枠は幅いっぱい＋左右の余白で、16px はみ出していた（今回の作業の途中で見つけて直した）。

## 3. 3つの道の切りかえ

- 説明の文（「〇〇が入った上位パーティと、集計の型」「条件を決めて、2つの考え方で案を作る」「1匹ずつ選び、そのたびに分析と候補」）を消し、**番号と名前だけ**にした。代わりの説明は足していない。
- 高さをそろえた（390px で3つとも52px。テストで差1px以内・44〜64px を確かめる）。選んでいる道はテーマの色の枠・うすい下地・番号の色。
- 389px 以下は番号の下に名前（3列のまま）。カード全体が押せる。

## 4. それぞれの部分

- **まとめ**（`tbSumHTML`）：数は `tbAnalyze` の結果そのまま（メガシンカなしの場合の大きな弱点・`tbTypes` の表・`miss`）。いちばんの問題は、大きな弱点を種類（MVP_WK の4つ）ごとに数えた並べ替えで、新しい判定は足していない。短い名前 `TB_WKS`（例：「交代で受けられる匹がいない」）は MVP_WK の言葉を縮めたもので、意味は同じ（全文は「くわしい分析」に）。
- **パーティ**：大きな枠6つ → 1行ずつ（アイコン・名前・型の出どころの短い名前・「入れかえ」「外す」）。育成と出典は「育成 ›」を押すと出る。空いた枠は「追加する（あと N匹）」の1行。
- **1匹ずつの働き**（`tbMemInfoHTML`）：1行に 名前・おもな役わり・いちばんの働き（その匹だけが答えられる相手の数 → なければ1対1で有利の数 → なければ安全に受けられる数）・注意（上位から一撃・重なる弱点、赤）。押すと「1対1で有利」「安全に受けられる」「後出しして勝てる」を**別々の行**で、数・相手・それぞれの意味つきで出す（混ぜていない・意味は前のまま）。
- **タイプの相性**（`tbTypesHTML`）：受けられる匹がいない弱点のタイプだけを、弱点の匹数の多い順に（2匹以上は赤）。どのタイプにも受けられる匹がいれば一言。18タイプの表は「18タイプの表を見る」の中（問題のタイプを上に並べた）。「半減以下で受けられても、交代で安全に受けられるとは限らない」を表の説明に足した（数の意味は変えていない）。
- **次に入れる候補**（`tbCandCard`）：名前・「大きな弱点 a → b件」（メガシンカなしの場合。無ければ最初の場合）・＋いちばんの理由（なくなる大きな弱点の1つ目と残りの数／なければ加わる役わり／なければ「大きな弱点は減らない」）・−気をつけること（新しい大きな弱点 → なければ重なる弱点タイプ → なければ小さな弱点の数）・「追加する」「いまの匹と比べる」。前の中身は全部「くわしく」の中に、なくなる／新しくできる弱点は件数を切らずに全部。並べ方（`tbCands`）は変えていない。
- **いまの匹と比べる**（`tbCmpHTML`）：「A → B：大きな弱点 a → b件」と、良くなる（なくなる大きな弱点、3件まで＋ほかN件）・悪くなる（新しい大きな弱点＋小さな弱点の数、メガシンカできる匹がいなくなるとき）・変わらない（残る大きな弱点の数）・その枠の働き（3つの数の前→後）。前の入れかえ案のカードは「くわしい比べ方」の中にそのまま。数はすべて `mvpCompare` のまま。
- **くわしい分析**（`tbMoreHTML`）：前の画面にあった大きな弱点の全部（`mvpWeakHTML`）・受けにくいタイプ・役わり・3匹以上の重なり・素早さ・相手の出典。
- ①の「このパーティを当サイトの計算で見る」も同じまとめ＋くわしい分析を出す（次の一手は出さない）。
- 開く行（18タイプの表・くわしく・くわしい分析・くわしい比べ方）は同じ形（テーマの色の文字＋›、開くと回る）。

## 5. 下の帯と下のメニュー

## 8. 残っていること（別に書いておくこと）

- **「大きな弱点 N件」の数え方**：同じ相手が2つの種類（例：有利な匹がいない＋受けられる匹がいない）に当たると2件と数える（前からの数え方）。「相手の数」と思われるかもしれない。意味は変えずに、いちばんの問題の行では「相手 N匹」と種類ごとに書いた。数え方を「相手の数」に変えるかは別に決めること。
- **役わり**は補助の技・特性（トリックルーム・おいかぜ・交代技・設置技など）だけで、攻撃役は数えていない（`mvpRoles` の作り）。攻撃役の匹は「補助の役わりなし」と出る。
- 6匹そろったときの入れかえ案は、前の入れかえ案の画面（`mvpResultHTML`）のまま（今回は手を付けていない）。
- ②・①の画面の中身は、切りかえのカード以外は前のまま。
- iPhone の実機では確かめていない（Playwright の 390px で確かめた）。

## 8.5 追加：安っぽさをなくす仕上げ（同日 依頼主「入れかえ・外すのボタンをはじめ、チープに感じる」）

依頼主のスクリーンショットは公開中の前の版（大きな枠6つ）だったが、作りかえた版にも枠線の丸いボタン（`.btn-s`）が多く残っていたので、見た目の作りを変えた（計算・並べ方は同じ）。

- **3つの道**：3枚のカード → 1本の帯の切りかえ（iPhone の設定画面のような形。選んでいる道だけ白い面と影、番号は小さな丸）。名前は1行に収まる短い形（環境のパーティ／こだわり条件／自分で組む。読み上げには元の名前「① 環境のパーティを見る」等）。379px 以下は番号を隠す。390px・320px で文字が切れないことをテストで確かめる。
- **パーティの行**：「入れかえ」「外す」の丸い枠のボタン → 枠の無い絵のボタン（回る矢印・×、40px、押すと薄い下地、外すは赤）。読み上げ用の名前（「ドドゲザンを外す」）つき。「追加する（あと3匹）」の点線の枠 → 塗りの行（テーマの色の丸い＋・「ポケモンを追加」・右に「あと3匹」）。
- **候補のカード**：下の大きな2つのボタン → 右上の小さな「＋ 追加」（塗り）と、文字のリンク「いまの匹と比べる ›」「くわしく ›」を1行に。「大きな弱点 9 → 7件」は後ろの数を大きく、減れば緑・増えれば赤。
- **比べる**：匹を選ぶボタンは塗りの小さな札（選ぶとテーマの色）、「〇〇と入れかえる」は幅いっぱいの塗りのボタン（回る矢印つき）。
- **まとめ**：「候補を見る」はリンクの形に。
- テストに2項目（入れかえ・外すは名前つきの絵のボタンで40px以上／パーティの行・候補のカードに枠線の丸いボタンを使わない）を足し、切りかえの確かめを帯の形に合わせた（下地の色で選んでいるか・文字が切れない・高さ40px以上）。teambuild 107項目すべて合格。

気になる点：絵だけのボタン（回る矢印・×）は、はじめての人に意味が伝わりにくいかもしれない（パソコンでは指を乗せると「入れかえる」「外す」と出る）。分かりにくければ小さな文字を添える。
